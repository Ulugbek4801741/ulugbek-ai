# Functions and Reusable Code Patterns

A function lesson must specify: name, purpose, input contract, output contract, side effects, errors, complexity, security assumptions and tests.

Core patterns to learn and compare:
- Pure function vs side-effecting procedure.
- Validation and normalization at system boundaries.
- Early return / guard clauses.
- Dependency injection and interface-based design.
- Adapter, strategy, factory, repository and observer patterns.
- Resource acquisition/release (RAII, context managers, defer, try/finally).
- Retry with bounded attempts, backoff and idempotency.
- Pagination, caching with expiry, rate limiting.
- State machine and finite workflow.
- Error/result propagation and structured logging.

Never paste a pattern without adapting naming, types, error semantics, concurrency model and framework conventions of the target language.
